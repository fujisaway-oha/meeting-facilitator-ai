## 2. 開発ルール・安全制約（人間・AIコーディングツール共通）

本プロジェクトでは、手作業およびAIエージェント（Antigravity / Cursor / Claude Code 等）を用いた開発の双方において、以下の安全ルールを**例外なく厳守**してください。

> [!IMPORTANT]
> AIコーディングツールを利用する場合は、本セクション（2.1〜2.5）の内容をツールのプロジェクトルール（Rules / `AGENTS.md` 等）にも設定した上で作業してください。

### 2.1 Git・ブランチ運用とリリースの境界
1. **本番ブランチ（`main` / `master`）での直接作業禁止**
   * `main` ブランチ上での直接ファイル編集、直接コミット、直接 `push` は一切行わないこと。
   * 必ず `develop` または作業ブランチ（`feat/xxx`, `fix/xxx`）を切って実装・検証を行うこと。
2. **本番ブランチへの自動マージ禁止**
   * AIエージェントやスクリプトによるマージコマンド（`gh pr merge`, 本番への `git merge` 等）の実行は厳禁とする。
   * 作業範囲は「作業ブランチでの実装・検証・PR作成・報告」までとし、**PRの最終確認およびマージボタンの押下は必ずプロジェクトオーナー（またはレビュアー）がGitHub上で手動で行う**こと。

### 2.2 破壊的・非可逆なコマンドの絶対禁止
以下の操作は、いかなる理由があってもスクリプトやAIエージェントで自動実行しないこと。
* システム・ルート領域の削除や権限変更（`rm -rf /`, `rm -rf ~`, `chmod -R 777` 等）
* リポジトリ履歴やブランチの破壊的操作（`git push --force`, `git reset --hard`, `git clean -f`, 無断の `git rebase` 等）
* データベースの初期化・全削除（本番／共有データの `DROP`, `TRUNCATE`, シードデータの上書き等）
* クラウドインフラの破壊・課金リスクを伴う操作

### 2.3 ファイル変更・機密情報・スコープ管理の原則
1. **機密情報・個人データの保護**
   * `.env`、`*.pem`、`id_rsa`、APIキー、認証トークンを含むファイルは、Gitへのコミットはもちろん、AIエージェントによる読み取り・変更・外部送信を行わないこと。
   * 環境変数の項目追加が必要な場合は `.env.example`（ダミー値のみ）を更新すること。
   * 会議の録音データ・SQLite DBが保存される `data/` ディレクトリは `.gitignore` 除外を維持し、絶対にリポジトリへ含めないこと。
2. **スコープ外の変更禁止**
   * 担当タスクと直接関係のない設定ファイル、依存パッケージ、既存ロジックを無断でリファクタリング・削除しないこと。
3. **段階的変更**
   * 大規模なファイル置換や構成変更を行う前に、まず変更計画・差分方針を合意すること。

### 2.4 パッケージ追加・外部ネットワーク接続の境界
* **事前確認を必須とする操作**：
  * 新規パッケージのインストール・依存関係の更新（`npm install`, `pip install` 等）
  * 開発サーバー以外の外部ネットワーク接続を伴うスクリプト実行
* **完全オフライン動作の維持**：
  * 本システムは社内閉域網の会議室でも動作する「完全ローカル完結」を要件としているため、外部CDN（Google Fonts, 外部JSポリフィル等）や外部クラウドAPIへの依存を追加しないこと。

### 2.5 フロントエンド・アバター実装規約
* **XSS防止**：音声文字起こし結果やLLM応答テキストの描画に `innerHTML` や `setHTMLUnsafe` を使用せず、`document.createElement` および `textContent` を用いること。
* **アバター描画層の分離維持**：将来的な Live2D / 3D VRM への移行を容易にするため、アバター表示の改修は `frontend/src/avatar/AvatarRenderer.ts` の `AvatarRenderer` インターフェースに沿って実装すること。

## 3. システム概要・技術スタック

* **コンセプト**：対面会議室のマイクスピーカー＋16:9横長モニターを介して会議に同席し、「書記役（4分類ボード整理）」「進行役（全画面アバター＋音声での声かけ）」「まとめ役（総括読み上げ＋議事録出力）」を担うWebシステム。
* **ターゲット環境**：
  * **本番機**：Linux (`aarch64`) / NVIDIA GB10 Grace Blackwell / 128GB Unified Memory
  * **開発・検証機**：大容量メモリ搭載 Mac（Mac mini 等）や一般的なDocker実行可能PC
* **構成技術**：
  * **Backend**：Python 3.11 / FastAPI / WebSocket / SQLite（WALモード）
  * **Frontend**：Vite + TypeScript（軽量SPA・16:9全画面スピーカービューHUD）
  * **Local AI**：Ollama（`config/models.yaml` でモデル指定）、`faster-whisper`（ローカル音声認識）、`VOICEVOX Engine`（Docker同梱・ローカル音声合成）

## 4. ローカル開発環境の起動手順

```bash
# 1. develop ブランチをクローン
git clone -b develop https://github.com/fujisaway-oha/meeting-facilitator-ai.git
cd meeting-facilitator-ai

# 2. Docker Compose でビルド＆起動（Mac / 一般PC）
docker compose up --build

# ※NVIDIA GPU搭載Linux機（GB10等）で起動する場合：
# docker compose -f compose.yaml -f compose.gpu.yaml up -d --build
```

1. ブラウザで **`http://localhost:8000`** を開き、初期パスコード **`1234`** でログインします（環境変数 `APP_PASSCODE` で変更可）。
2. ホストPC側で `Ollama` が起動していれば、`host.docker.internal:11434` 経由で自動接続されます（未起動PCでも内蔵デモモードで画面と音声対話を一通り確認できます）。

## 5. 実装済み機能（`develop` ブランチ時点）

* **全画面アバターUI（16:9スピーカービュー）**：
  * 下部に直近4件の文字起こし＋AI発話字幕の半透明オーバーレイを常時表示
  * 最下部に Zoom / Meet 風のコンパクト通話ドックを配置
  * 右側の半透明サイドドロワー（`<dialog closedby="any">`）で、背面にアバターを残したまま「4分類議事ボード」「全文ログ・手入力」「設定・会議切替」を開閉可能
* **双方向音声対話 ＆ エコー抑止**：
  * 「🎙️ 声でAIと話す」から発話終了（約1.2秒の無音）を自動検知して `faster-whisper` で文字起こし → ボード反映 → `VOICEVOX` 音声＋口パクで返答（連続会話モード対応）
  * AI発話中＋終了後300msのマイク遮断（自己音声エコー抑止ゲート）
  * 声で「会議を締めてください／まとめて」と話しかけると、自動でまとめ役が起動し総括読み上げ＋確定議事録モーダルを表示
* **SQLite永続化 ＆ 課題引き継ぎ**：
  * 手動追加ロック（`🔒保護`：AI自動更新による上書き防止）
  * 新規会議作成時に前回の「素材待ち」「未決定事項」を自動プリロード（Carry-over）
